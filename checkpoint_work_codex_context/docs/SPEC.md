## コア要件
ここでの「要件」は期待する動作であり、実装済みを意味しない。
| ID | 期待する動作 | 根拠・位置づけ |
|---|---|---|
| CP-01 | 目的・権限用途・端末内保存について初回説明 | 原要件・商品計画 |
| CP-02 | 使い終わった後の帰還点を設定し、変更・終了まで保持 | 差別化FR-01〜02 |
| CP-03 | 対象アプリ開始時に目的・予定時間・帰還点を確認 | 差別化FR-03 |
| CP-04 | 一つの目的を一つのセッションで管理 | 差別化FR-04 |
| CP-05 | 別の対象アプリへ移動した時、続き／別目的／開かないを確認 | 差別化FR-05 |
| CP-06 | 続きなら目的・帰還点・時間を引き継ぐ | 差別化FR-06 |
| CP-07 | 別目的なら現在のセッションを終了し、新しい目的を設定 | 差別化FR-07の基本案 |

| CP-12 | 権限不足・サービス停止を正しく表示し、設定へ案内 | 原要件・商品計画 |

## 時間計測：実装前に決める
差別化要件は対象アプリの前面利用時間を合算し、HOME・除外アプリを含めない。商品計画は現実装がdeadlineと時計の差と報告している。
前面時間方式を候補とするが、このキット作成だけで方式変更を承認・実装したとは扱わない。TASK-001で現状を確認し、TASK-002を実行可能にする前に決定する。
ロック中、確認オーバーレイ中、通知シェード、画面分割、サービス再生成時の扱いも決める。

## データ・復習・対象選択
画面内容の取得とクラウド行動保存は非目標。記録は端末内を基本とし、HOME復帰と実際の勉強復帰を区別する。
差別化要件の「分析保存不要」は必須でないという記述。商品計画にはローカル記録がある。保存項目・削除・保持期間はコード調査後に明確化する。
復習問題は任意の学習支援候補。通常フローを必ず問題で止める仕様にはしない。
原要件の全通常アプリ対象と商品計画の対象アプリ選択には差がある。対象選択・自動除外の実態を確認し、方針を決定する。
