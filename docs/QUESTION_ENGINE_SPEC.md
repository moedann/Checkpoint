# チェックポイント：問題エンジン＋外部作問 要求仕様 v0.1
2026-10-12／**設計草案（アプリへの実装やコミットではない）**

## 0. 既存製品への位置づけ
製品の主題はスマホを使う目的の認識と元の行動への帰還。学習を支援する「復習問題」機能をオプションとして統合する。
対象ユーザーの初期仮説：資格試験の受験者、大学受験の高校生。どの資格や教科にも固有実装を増やすのでなく、問題形式と試験メタデータを分ける。
通常の目的セッション（帰還点・予定時間・アプリをまたぐ目的継続）は既存CP-01〜12を維持する。学習ゲート機能はCP-Q01〜とする。

## 1. UX：学習チェックポイント
- ユーザーが学習ゲートを有効化し、問題集・対象アプリ・1回の出題数を選ぶ。初期提案は1問、通常目的確認は別に維持。
- 対象アプリの起動イベントが来たら通常目的確認の文脈を失わず、復習問題を提示する。複数の画面や確認を無用に重ねず、開始体験を統合する。
- 問題に取り組んで解答を提出（形式に応じて入力完了の確認）→答え合わせ画面を表示→ユーザーが確認→「対象アプリを使う」または「勉強を続ける」を選ぶ。
- 正解・不正解・部分正解・自己採点のいずれでも解放する。**解放の条件は答え合わせの確認であり、正答ではない**。
- 「勉強を続ける」は問題集へ移動して追加学習する（新たな対象アプリの強制ゲートではない）。「対象アプリを使う」はゲートを完了して元の起動対象を操作可能にする。
- 対象アプリが見当たらない・権限が失効・割り込み・緊急通話等の場合は安全な終了／一時スキップを用意。復習データがない・取り込み失敗なら繰り返しブロックせず、状況を説明して利用を続けられる。
- 音声再生やテキスト入力が必要な問題はオーバーレイ内の窮屈な画面に押し込めない。起動直後の軽量オーバーレイ→独立した全画面問題プレイヤーへ遷移できるよう技術検証。AndroidのActivity起動制約を確認し、保証できない挙動を仕様化しない。

### 推奨画面遷移
```
対象アプリを起動
  └ 学習ゲートOFF → 既存の目的確認へ
  └ 学習ゲートON → 目的確認と今回の復習の入口（繰り返し入力を省く）
       → 共通問題プレイヤー（6方式のいずれか）
       → 解答提出（未回答チェック／自己採点の例外）
       → 答え合わせ（正解、解説、必要ならセル別の結果）
       ├ 対象アプリを使う → 共通目的セッション継続
       └ 勉強を続ける → アプリ内学習画面へ
```
※実機で起動先復帰が不安定ならユーザー操作による起動先への復帰等の代替方式を設計。

## 2. 必須の6回答方式：表示・操作・採点

| 外部形式名 | 内部形式 | 表示と回答 | 採点規則（初期） | 境界条件 |
|---|---|---|---|---|
| 1. 単一選択 | `single_choice` | 選択肢2件以上。1個のみラジオ選択 | 正解の**選択肢ID**と一致 | 4/5択固定にしない。選択肢シャッフルしてもID比較 |
| 2. 複数選択 | `multiple_choice` | 複数選択、問題別の選択上限・下限 | 正解ID集合との完全一致。結果画面で過不足表示 | 正解数指定／指定なしに両対応。順不同 |
| 3. テキスト・数値入力 | `entry` | 複数独立フィールドに短文／数値を入力 | テキスト許容解一覧、数値の単位・絶対/相対許容差 | 表記揺れは問題ごとに指定。桁区切り、負数、空欄、途中過程 |
| 4. 構造化入力 | `grid` | 行×列の表、静的セルと入力セルを混在 | 入力セルごとの文字/数値採点、全一致とセル別結果 | 表の拡大、列固定、左右スクロール、読み上げ |
| 5. 操作式 | `interaction` | `ordering` 並べ替え、`grouping` 分類 | 並びID列の完全一致／項目ID→グループIDの一致 | ドラッグ操作のほか移動ボタン・選択UIを提供 |
| 6. 語群選択・穴埋め | `word_bank` | 本文中の複数空欄へ語群トークンIDを選択配置 | blankID→tokenIDで判定 | 語の重複表示、再利用の可否、空欄数が可変 |

**補助形式** `self_review`：紙・PC上で解く長文記述、口頭、実技等。問題提示→「取り組んだ」→模範解答／評価基準を見て自己採点→先へ進む。採点不能を誤って自動正解にしない。

### 採点共通仕様
- 評価は `correct | partial | incorrect | self_reviewed | ungraded` の結果とセル／項目別の詳細を持てる。ただしリリース条件は必ず `review_acknowledged`。
- `not_answered` は回答前の状態。単一選択未選択・複数選択0個（空集合が正解の問題以外）・指定必須フィールド空白は提出できない。
- テキストの初期正規化は前後空白除去／Unicode NFKC（問題別に無効可）。大文字小文字・全角半角・空白許容／類義語は問題作成側で指定する。自動意味判定は採用しない。
- 数値は入力文字列からロケール配慮して解析する。`expectedValue` と `absoluteTolerance` / `relativeTolerance` を比較する。桁区切り、単位は明示した規則のみ。丸めは勝手に推測しない。
- 複数選択の部分点は結果表示用。正誤以外にも「選択数超過」等を検出できるが、アプリ利用可否に利用しない。
- 仕訳／計算表は入力セルが複数あり、正解セルを順序付きで提示。最終結果は `correct` か `partial` か等を表示する。
- 外部作問の正答を絶対視しない。「答えに誤りがある」報告／正解修正を可能にし、AI生成にはレビュー注意を表示。

## 3. 出題データと試験のメタ情報
- **1問1形式**。問題集 (`QuestionPack`) は問題の配列、出典と作者、分野・試験名・級／科目・タグ・版情報を持つ。
- 同じ試験名でも級、実施方式、学科と実技を分けてタグを付与可能。188資格はあくまで検索・分類の候補、問題の実例・正答の保証ではない。
- 1つの本文が共通で複数小問を持つ設問群 `passageId` / `groupId` の拡張を予定する。MVPは各問に同じ本文を置くか同一読解素材を参照して対応。
- 問題の標準表現はテキスト、数式、表、画像、音声を段階追加できる `stimulus` ブロック方式。原則画面内テキストの収集不要。
- 初期データ形式 `*.cpq.json`（UTF-8 JSON）。画像・音声付き問題用は `*.cpqpack`（manifest/JSON/assetsのZIP）を予定。外部URLへの勝手な取得は行わない。
- 正答（answerKey）と解説を持つため、暗号化・秘匿を前提とした高額試験問題販売用DRMではない。外部配布時の許可・権利を明示する。
- 解答履歴は別テーブル `QuestionAttempt` に保存。問題本文・作者情報と利用者の履歴・スマホ利用ログを混ぜない。

## 4. 外部で問題集を作成／生成し、取り込む：必須の製品体験
**原則：作る場所と解く場所を分離する。端末上の手入力だけに依存しない。**

### 4-A. ユーザーが外部Webで手作り
- PC・タブレット・他端末のブラウザで問題エディタを開く。
- 「単一選択／複数選択／テキスト・数値／表／並べ替え・分類／語群穴埋め」を選んで設問、正解、解説、タグを編集。
- プレビューで採点を試し、`cpq.json` または `cpqpack` を出力。まずはローカルでブラウザ内保存・エクスポート（ログインなし）を設計。クラウド同期は後工程で別仕様・同意。
- Android側はファイルを選んでプレビュー → 形式検証・重複検出 → ユーザー確認で登録。

### 4-B. 外部の生成AI（ChatGPT/Gemini等）を使用
- ユーザーが「ITパスポート10問」「数学の二次関数5問」等を外部AIに依頼し、**公開フォーマットに沿ったJSON** を生成させられる。
- `QuestionPack` スキーマ・サンプルと固定した作問用プロンプトを公開。JSONスキーマに違反した生成結果はどの項目が誤っているかを示し、再生成・手修正ができる。
- 正解と解説は利用者によるプレビュー確認を推奨し、出典不明／著作権不明な内容は公開共有させない。外部AIへの個人履歴・他アプリ利用ログの送信はしない。
- API統合でアプリ内「AI作問」を行う案は将来の別フェーズ。MVPでは外部AI経由のファイル取り込みだけで成立。

### 4-C. 表計算ソフト・既存問題の移行
- CSV/Excel等で自作・編集した表から読み込む経路を用意。単一選択・複数選択・短文等はCSVマッピングウィザードで対応。複雑な表・操作式はWebエディタ／JSON経由。
- 任意の既存テキスト／PDF／画像から問題を起こす際は、抽出の誤読、版権、正答検証を分ける。PDFやOCRを必須機能にしない。

### 4-D. 共有・再利用（後続）
- 問題セットの編集・複製・履歴・エクスポート。ファイル/共有シートによる受け渡しから開始。
- 共有URL・QR・アカウント同期・公開問題マーケットは別段階。プライバシーと権利申告が必要。単なるリンクを送って自動で外部サイトのコードを実行する設計は禁止。

### インポート安全基準（初期）
- スキーマ検証→論理検証（同一ID、解答キーの存在、順序・グループ、表のセル整合、語群トークン数、説明文欠落）→プレビュー→明示同意→端末内登録。エラー位置を示し全破棄せず修正可能にする。
- 未信頼のJSON・ZIPをHTML、JS、正規表現、数式評価として実行しない。パス走査とZIP爆弾、大容量素材、拡張子偽装、外部URL自動フェッチを拒否。
- 初期容量上限の候補：パック2000問・総容量100MB・単一アセット50MB。性能測定で調整する**仮置き**値。
- ファイルは端末内に保存し、取り込み時に作者と出典、利用許諾のチェックを表示。問題作成者による送信や公開を当然視しない。

## 5. データモデル（論理）
```
QuestionPack(packId, formatVersion, title, authorName, source, examInfo, locale, questions[], revision)
Question(id, type, prompt, stimulus[], payload[type], answerKey, explanation, tags, source, groupId?)
QuestionAttempt(attemptId, questionId, packId, startedAt, submittedAt, reviewedAt, answerPayload,
                gradeResult, gradeDetails, selfGrade?, gateId?)
LearningGate(gateId, targetPackage, purposeSessionId?, questionAttemptIds[],
             state=OPEN|PRESENTED|SUBMITTED|REVIEWED|UNLOCKED|BYPASSED, bypassReason?)
ReviewRule(enabled, selectedPackIds[], targetPackages[], questionCount=1, samplingStrategy)
```
採点はモデルに対する純粋関数、UIに依存しない。問題と解答の型は共通インターフェースで統合する。

## 6. 技術方針（実装確定ではなく検証課題を含む）
- Flutter：問題集管理・ファイル選択・形式プレビュー・6形式のリッチな解答画面と答え合わせ・アクセシビリティUI。
- Kotlin：起動検知・安全な介入タイミング・現在の目的セッションとの連携・オーバーレイとActivity間の遷移・HOME復帰などOS依存部分。
- プロセスが落ちても回答前／解説確認済の区別が壊れないよう遷移状態をローカル永続化。二重イベントで同じ問題を2枚開かない（gateIdによる冪等処理）。
- JSON Schema等の形式検証だけで採点の正当性は保証できない。ドメインの論理検証とテストフィクスチャを分離。
- 端末の画面内容を勝手に取得しない。ネットワーク送信・新権限・公開ストアのAccessibility申告は別途審査。

## 7. 実装の順序
1. **TASK-003**：共通モデル、6タイプのデータ検証、採点、JSON import/export、サンプルテスト。外部作問が先に始められる基盤。
2. **TASK-004**：Flutter 6方式プレイヤー／結果画面。ordering/groupingは非ドラッグ代替を同時設計。
3. **TASK-005**：ファイル取り込みのUX、外部Web作問（第一段階はローカルエクスポート）、AI/CSV作成テンプレート。Webエディタの公開は別デプロイ工程。
4. **TASK-006**：オーバーレイのゲート統合と目的セッション整合、安全な解放・例外処理、実機検証。

各段階で成功したテスト・まだできていない実機検証・GitコミットをSTATUSに記録。先に進む前に現行コードの復習機能とインポート実装を監査して、重複実装を避ける。

## 8. まだ検証されていないこと
- Android上の別アプリ起動直後の全画面解答プレイヤー遷移と、戻る際の起動先復元。
- 既存復習機能の実際のコード構造、履歴DB、インポート形式。
- 各資格試験の特殊出題操作・正式採点規則と、この6形式の対応率。
- 実機での画面サイズ、アクセシビリティ、音声再生、ジェスチャー操作。
- 外部Webエディタの利用需要、サーバー費用、著作権運用。
これらは**実装済み・検証済み**と表記しない。
